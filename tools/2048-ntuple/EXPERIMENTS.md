# 实验结果与复现

更新：2026-10-05 UTC。结果属于本 JavaScript 实现，采用标准 4×4 2048 规则。

## 最终独立评估

**100 局中 49 局合成 32768：49.0%。95% Wilson 区间为 39.4%–58.7%。** 下界高于 1/3；在这个测试分布和配置下，数据支持目标达成，但不构成任意未来游戏的胜率保证。

- 全部 100 局完整结束；0 中止、0 时限触发、0 缺失、0 重复种子
- 最大块分布：4096 × 1、8192 × 5、16384 × 45、32768 × 49
- 首次合成 32768 即停止；该次合并后的随机生成不影响“是否达到目标”，因此不再生成
- 真实输局必须无任何合法移动；不会因较差估值、搜索超时或未到目标而假记输局

### 后续边界校验变更的归属

当前工作版本在公开 `evaluatePacked(lo, hi)` 边界拒绝非法 uint32 参数，并以模块私有查表路径避免在内部叶子重复校验。权重、表结构、特征顺序、合法棋盘搜索公式和目标终止规则未变；这是合法输入行为保持的校验加固，不是模型升级或向 65536 扩展。

上述 49/100 和耗时仍只归属于表中冻结源码 SHA-256 `ab2e0c4eca2e84061602f9d4b80a45debd9986a35a618f32478cb0ae097261ed`，原文件保存在 `results/development-selective-v3-source/ntuple2048.js`。新增边界回归用合成权重验证 4x6/8x6 范围，以及与该冻结版本的精确决策、值和查表序列一致；未重新下载权重、未重新跑独立一百局，不能把原实验重新标记为修改后源码的实测成绩。原协议、原始结果和冻结档案保持原样。

## 规则

- 4×4；真实块值使用 2 的整数次幂
- 两次独立初始生成
- 每次改变棋盘的合法移动后，均匀选择空格，90% 生成 2 / 10% 生成 4
- 每局 Mulberry32 单独种子；位置随机数先于块值随机数
- solver 只接收棋盘，生成 RNG 保留在实验驱动内部
- 2048 与 16384 不触发提前获胜；目标始终为第一次 32768

## 环境与速度

Linux x64，Node.js v24.19.0，INTEL(R) XEON(R) PLATINUM 8573C；共享云运行环境，最多两个游戏进程并行。实际执行：

- 开始：13:05:10.833 UTC；结束：13:09:59.597 UTC
- 总墙钟：**288.764 秒（4 分 49 秒）**
- 单局平均墙钟：**5.635 秒**
- 按移动数加权的平均决策：**0.398 ms**
- 峰值单进程 RSS：**640.70 MiB**
- 两个进程的模型加载/校验分别为 **1.111 秒、1.072 秒**，单独记录，未计入单局游戏时长
- 共 1,390,921 次有效移动，其中选用两层 1,222,867 次，选用第三层 168,054 次（约 12.1%）

这些是该环境的实测速度，不保证其他设备/负载相同。双精度 JavaScript 累加与原版 C++ float 的最后舍入可能不同，所以不宣称跨语言轨迹逐位相同。

## 原始数据与独立核验

- `results/independent-seeds61001-61050.jsonl`
- `results/independent-seeds61051-61100.jsonl`
- `results/INDEPENDENT_AGGREGATE.json`
- `results/INDEPENDENT_RUN_STATUS.json`
- `results/INDEPENDENT_REVIEW.json`

每局包括种子、完整终局、得分、有效步数、轨迹 SHA-256、耗时、决策分位数、实际层数分布和内存。分析脚本验证终局合法性，按种子独立重放生成数值流以核对总质量，再使用合并得分恒等式核对得分。另一份独立 Python 审查也对全部 100 局通过了这些检查。

为避免发布无关的运行环境绝对路径，公开 JSONL 中 `--model`、`--out` 的路径被规范化，并附有 `commandPathRedaction` 说明；配置、种子、源码/模型哈希和测量数据不变。

复现单进程完整种子集合（通常比双进程总墙钟长，但决策不依赖时钟）：

```sh
node benchmark-ntuple.js --model models/8x6patt.json \
  --seed 61001 --games 100 --ply 2 --critical-empty 1 --critical-tile 8192 \
  --max-seconds 15 --out results/reproduced-61001-61100.jsonl
```

输出排他创建，不覆盖既有结果。机器慢而触发时限时，必须保留中止状态；不能只删去慢局后作完整胜率结论。

## 开发决策过程（不是独立评估）

先用种子 60001 做了一局 4x6/2-ply 速度探针：1.78 秒完成，止于 16384；记录为 `results/pilot-ply2-seed60001.jsonl`。它与后续固定十局门槛分开报告。

所有开发门槛完整结束，无时限触发。选择模型/策略后才冻结并测试新的一百局；**不会把开发阶段 8/10 的 80% 当作最终无偏估计**。

对应开发协议、原始 JSONL、汇总及确切源码档案均在 `results/`。选择性开发门槛早期通用 metadata 描述仍写“两层”，其 `criticalSearch` 选项与 `actualPlyHistogram` 正确记录第三层；最终驱动已澄清文字，搜索没有因此改变。

## 正确性覆盖

- 4x6：18 组，含真实模型、288 个原始/转换数据逐位样本
- 8x6：14 组，含 64 模式特征、576 个逐位样本、独立原始权重参考的 1-/2-ply 决策和值
