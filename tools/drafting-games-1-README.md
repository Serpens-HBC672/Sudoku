# 制图台 2048：权重接口使用说明

适用页面：`tools/drafting-games-1.html`。保留原有 2048、数字华容道、动画、极速和连续对局功能；新增本地权重选择与后台推理。无需权重时仍可选择「原有启发式」。

## 1. 下载并转换权重（只需一次）

在仓库根目录运行，要求 **64 位 Node.js 22 或更新版本**；自动下载使用 `curl`：

```sh
node tools/2048-ntuple/prepare-model.js --network 8x6 --download
```

该命令下载作者公开、MIT 授权的固定版本 `8x6patt.w`，验证来源 SHA-256，然后提取推理表，生成：

- `tools/2048-ntuple/models/8x6patt.f32`：**网页需要选择的文件，512 MiB**
- `tools/2048-ntuple/models/8x6patt.json`：模型来源及格式记录，供 Node.js 接口使用

网页不能直接加载原始 `.w`、`.json`、4x6 权重或其他训练模型。原始下载约 1.5 GiB，连同转换文件约需 2 GiB 磁盘。下载未完成时重新运行同一命令可续传；已生成完整文件时不必再运行，工具不会覆盖它们。

已有原始文件时可以只转换：

```sh
node tools/2048-ntuple/prepare-model.js --network 8x6 \
  --source /你的路径/8x6patt.w --out tools/2048-ntuple/models
```

输出目录应尚未存在同名完整转换结果。权重不会加入 Git，也不需要上传到网站服务器。来源、许可证及完整哈希见 [MODEL-PROVENANCE.md](2048-ntuple/MODEL-PROVENANCE.md)。

## 2. 通过本地 HTTP 打开页面

在**仓库根目录**运行，例如使用 Python 3：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows 可使用 `py -m http.server 8000 --bind 127.0.0.1`。

浏览器打开：

```text
http://127.0.0.1:8000/tools/drafting-games-1.html
```

不要只双击 HTML 使用 `file://`；浏览器可能阻止 Worker 加载相邻脚本。也可以部署这些代码文件到同源 HTTPS 静态站点，但**不必部署权重文件**。

保留以下目录关系：

```text
tools/
  drafting-games-1.html
  drafting-games-1-README.md
  2048-expectimax/
    expectimax2048.js
  2048-ntuple/
    ntuple2048.js
    browser-adapter.js
    browser-worker.js
    browser-sha256.js
```

其余准备、测试、说明文件按仓库原样保留即可。无需 npm 安装运行时依赖。

## 3. 页面操作

1. 在 2048 下方「本地权重文件」选择 **8x6patt.f32**。选择后自动切换到 TD 8×6 策略。
2. 等待进度完成，看到「8x6 权重已就绪 · SHA-256 已验证」。校验完成前 TD 自动游玩按钮不可用，手动游戏仍可操作。
3. 点击「自动游玩」。普通模式保留动画；「每步间隔」控制节奏。如果计算超过间隔，完成后再走，不截断搜索。
4. 需要最快速度时，先停止，再打开「极速」并重新开始。TD 极速不插入额外等待，也不使用原有启发式的墙钟预算。
5. 「停止」、新局、切换策略或切换到数字华容道都会取消当前自动落子；新局可复用已加载的权重。
6. 「取消加载」立即终止读取；「释放权重」终止权重线程并释放其内存。刷新或离开页面后需重新选文件。

文件仅在当前浏览器中读取，页面没有上传权重的网络请求。权重读取、SHA-256 校验、查表与搜索都在专用 Web Worker 中完成，主线程不持有另一份完整模型。校验使用一个最终模型缓冲区与 4 MiB 小块。

建议桌面 64 位浏览器，并预留 **至少 1 GiB 可用内存**；浏览器本身和其他页面还需要额外内存。手机、低内存设备及受限浏览器可能无法分配 512 MiB，不保证支持。

## 4. 策略与限制

固定配置：**8×6 N-tuple TD，常规 2-ply；当前棋盘空格 ≤1 且最大块 ≥8192 时使用 3-ply；目标 32768**。这与独立 100 局评估的推荐配置一致。那次 Node.js 实验 49/100 局达到目标，不能保证每三局必胜，也不是浏览器端重新测得的成绩。

- TD 达到 **32768 即停止**，记录为一局；开启「连续对局」则稍后自动开新局。可停止连续对局，然后手动继续，或选择原有启发式继续挑战更高块。
- TD 不支持原有「动态预算」，该按钮在 TD 模式禁用；极速也不会改变验证过的搜索层数。
- 策略只接收当前棋盘，枚举 90% 生成 2 / 10% 生成 4 的期望；不接收种子、未来随机数或下一次生成位置。
- 目前只接受固定版本 8x6 推理文件，完整 SHA-256 必须为 `4e9342fa525ae41d5268e294f396dd066822cd9df88076b864d35f356f3f3297`。
- 原页面没有撤销按钮，本次没有新增撤销功能。

## 5. 集成接口

`NTupleBrowser.boardFromTiles(tiles)` 把页面的 `{r,c,exp}` 方块转换为**行优先的 16 个真实数值**；例如 `exp:1` 转成 `2`，空位是 `0`。方向严格映射为 `0=up、1=right、2=down、3=left`。

`NTupleBrowser.createClient({onState})` 提供 `load(file)`、`ask(board)`、`cancel()`、`unload()` 和只读状态副本 `state`。`ask()` 返回 Promise；取消或替换的请求返回 `{cancelled:true}`。加载后复用同一 Worker 和模型。加载失败不会默默切换成另一种 AI，页面会显示原因。

页面也提供 `window.Drafting2048`：

- `getState()`：返回当前真实棋盘和分数等信息的副本
- `move('up'|'right'|'down'|'left')`：停止自动游玩后执行手动移动
- `newGame()`、`start()`、`stop()`

页面使用请求编号、自动游玩令牌、棋盘版本及当前棋盘比对拦截过期结果。动画结束回调只处理显示，不会向重开的新局补发旧随机块。若后续增加撤销或直接替换棋盘的功能，也必须先停止自动游玩并更新棋盘版本。

## 6. 常见问题与检查

- **大小/格式错误**：选择转换后的 512 MiB `.f32`，不要选 `.w` 或 JSON。文件扩展名不是验证依据，完整大小和哈希都要匹配。
- **SHA-256 不匹配**：文件损坏或模型版本不对。重新获取固定版本并转换，不要跳过验证。
- **后台线程启动失败**：确认使用 HTTP(S)、四个相关 JavaScript 文件和相邻 `expectimax2048.js` 都在正确位置，站点允许同源 Worker。也可能内存不足。页面仍可选择原有启发式或手动游戏。
- **加载/运行无响应**：无进度超过 60 秒会显示错误并停止线程；可重新选文件。期间可以点击「取消加载」。慢设备上校验完整 512 MiB 需要一定时间。
- **TD 到 32768 后不能重新点自动游玩**：这是目标边界。开新局或切换原有启发式即可。

无需权重的测试：

```sh
cd tools/2048-ntuple
npm test
```

测试包括核心数值测试、848 项哈希/方向/真实移动映射检查、Worker 请求取消，以及实际 HTML 脚本的 DOM/时钟生命周期模拟。另已用完整真实 8x6 文件测试后台读取、完整 SHA 校验和与 Node 直接调用一致的搜索结果。

**验证边界**：本次云运行环境阻止 Chromium 创建所需 socket，托管浏览器也阻止 localhost；因此没有完成真实浏览器的渲染、文件选择器、CSP 和移动端兼容性验收。DOM 模拟和 Node Worker 合约测试不能代替这些检查。交付后建议在目标桌面浏览器按上面步骤完成一次加载、自动游玩、停止和新局冒烟检查。
