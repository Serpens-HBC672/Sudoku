# Android packaging and GitHub Release

This repository keeps the Sudoku application as its existing single HTML file. The mobile packaging layer does not rewrite the Sudoku engine. During CI, `scripts/prepare-web.mjs` copies the single root `Sudoku *.html` file to `www/index.html`, then Capacitor generates the Android project.

## What gets built

Every Android Release run publishes these files to the repository's **Releases** page:

- `Sudoku-vX.Y.Z-android-test.apk` — installable phone-validation APK, always produced.
- `Sudoku-vX.Y.Z-android-test.aab` — validation Android App Bundle, always produced.
- `SHA256SUMS.txt` — checksums for all packages.

If production signing secrets are configured, the same Release also contains:

- `Sudoku-vX.Y.Z-android.apk` — production-signed APK.
- `Sudoku-vX.Y.Z-android.aab` — production-signed App Bundle for store submission.

The `-android-test.apk` exists deliberately so phone testing is never blocked by missing production signing secrets. CI debug signing is not a stable upgrade identity, so if a later test APK reports a signature mismatch, uninstall the previous test build first. Production-signed builds do not have this limitation as long as the same release key is retained.

## Publish a phone-test release

After the packaging PR is merged to `main`:

1. Open **Actions** in GitHub.
2. Select **Android Release**.
3. Choose **Run workflow** on `main`.
4. Enter a new tag, for example `v3.19.23-rc.4`.
5. Leave **Publish as a GitHub pre-release** enabled for an `rc` build.
6. Wait for the workflow to finish successfully.
7. Open **Releases** and download `Sudoku-v3.19.23-rc.4-android-test.apk` directly on the Android phone.
8. Allow installation from the browser/file manager if Android asks, then install and test the app.

Pushing a Git tag matching `v*` also triggers the same release workflow. Tags containing a pre-release suffix such as `-rc.4` are automatically treated as pre-releases when triggered by a tag push.

A release tag is immutable in this workflow: if a tag already points to a different commit, the workflow fails and requires a new version tag instead of silently replacing old release binaries.

## Production signing

Never commit a keystore or its passwords to the repository. Configure these GitHub Actions repository secrets when production-upgrade/store packages are needed:

- `ANDROID_KEYSTORE_BASE64` — base64 encoding of the `.jks`/`.keystore` file.
- `ANDROID_KEYSTORE_PASSWORD` — keystore password.
- `ANDROID_KEY_ALIAS` — signing key alias.
- `ANDROID_KEY_PASSWORD` — signing key password.

Example for creating the base64 value locally on Linux/macOS:

```sh
base64 < sudoku-release.jks | tr -d '\n'
```

Keep the original keystore backed up outside GitHub. Losing it can prevent future APK updates signed with the same application identity.

## CI behavior

`Android CI` runs for pull requests and pushes to `main`. It builds an installable debug APK and AAB and stores them as workflow artifacts. This catches Android/Capacitor build failures before a release.

`Android Release` runs only for `v*` tags or manual dispatch. It builds the packages, creates the GitHub Release when needed, uploads the files, and finally verifies that the installable `-android-test.apk` is actually present in the Release assets.

## Toolchain

- Node.js 22
- Capacitor 8.5.1
- Java 21
- Android project generated by Capacitor during CI

The generated `www/`, `android/`, `node_modules/`, and signing-key files are intentionally ignored and are not source-controlled.
